# A changed user identifier silently drops composite joins

An explicit identifier map restored all 100 activity matches in this synthetic incident, recovering 40 matches that an inner join silently discarded. The measured recovered share is 40 divided by 100 input activities, or 40%. The broken join retains 60 matches; the corrected join retains 100. These numbers come from the generated fixture and executed models. They describe a portfolio exercise, not an employment incident, customer loss, or measured commercial outcome.

The source contains two tenants with fifty users each. The canonical dimension stores numeric-looking identifiers as text. Activity records for later users switch to a prefixed upstream representation such as `usr:31`, while earlier users retain their original representation. The injected bug joins activity directly to the canonical dimension using tenant and raw user identifier. The query completes successfully because both sides are valid strings, but the changed representations no longer compare equal. A successful job therefore gives no assurance that it preserved expected relationships.

Discovery begins with the raw activity records rather than only the joined output. `investigation.sql` performs a left join on the original composite key and selects unmatched records. The executed evidence lists the affected tenant and raw identifier pairs. Both tenants show the same format boundary, which points to a representation change rather than an absent tenant or a failed ingestion batch. Keeping the raw identifier visible makes that conclusion inspectable. Looking exclusively at the surviving inner-join rows would hide precisely the evidence needed to explain the loss.

The fix uses a small explicit mapping from changed raw identifiers to canonical identifiers. It leaves already canonical values unchanged through a fallback and keeps tenant equality in the final join. Removing the tenant predicate would create cross-tenant matches because user identifiers repeat across tenants. The map is globally scoped only because this synthetic upstream format transformation has the same meaning for both tenants. If mappings differed by tenant, the mapping key would also need tenant identity, plus constraints preventing ambiguous or duplicate mappings.

Run `make case-2` after `make setup` to generate the data, build the models, execute the investigation, and replace this case's machine-readable results. The recovery denominator is total raw activity, not the surviving matched subset. A different metric, such as recovered share of originally missing activity, would answer a different question. Reporting the denominator explicitly makes the 40% figure usable by another reader or a website consuming the JSON without guessing what the percentage means.

The regression query computes raw composite identities missing from the transformed output. It returns forty identities against the broken relation and zero against the fixed relation. A dbt non-null check supplements that coverage assertion, while pytest checks total output and preservation of the fifty-row tenant boundary. These checks protect against this fixture's silent loss; they are not a universal identity-resolution system. Further real-world requirements would include map uniqueness, unknown-format quarantine, and ownership of future contract changes. The committed SQL, generator, and results make the demonstrated recovery independently reproducible and keep those broader production concerns separate from what was actually validated here.
